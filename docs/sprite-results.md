# Accuracy ROM results

Generated by `dotnet run -c Release --project tests/NesEmulator.Tests -- --sprite-suite roms/accuracy docs/sprite-results.md`.

The fetch script pins [nes-test-roms](https://github.com/christopherpow/nes-test-roms/tree/95d8f621ae55cee0d09b91519a8989ae0e64753b). Each row records the SHA-256 of the ROM actually tested.

These older ROMs use the result protocol in their supplied `validation.a` and `runtime_rom.a`: PASS requires `$00F8 = 1` after the CPU reaches a `JMP` to its own address. A result byte alone is insufficient. Other terminal codes are failures; a run that never reaches the terminal loop is a timeout. No screenshot is treated as a pass.

The sprite-zero-hit and sprite-overflow groups each run in their documented order. Results are separate from the original 55-ROM baseline.
